# pcl2-download-unlocker

> 基于 DeepSeek V4.1F-1017 面向结果许愿式编程诞生的项目
> 主要用于解锁 PCL2 启动器下载限制，并附带屏蔽更新功能
> 用于解决眼前难题，**后续不做维护**

一个对 **Plain Craft Launcher 2（PCL2）** 可执行文件做"等长字节改写"的小工具：
把下载页里那个只会抛"为遵守相关法律法规…"的空任务换成真正的版本清单加载器，从而恢复
"安装新游戏"的版本列表与安装能力；另可选择屏蔽启动器更新检测与自动更新。

- 不安装、不联网、不需要管理员权限（目标目录可写即可）
- 只修改你指定的那一个 exe，文件大小、RVA、资源、强名称状态全部不变
- 定位失败时**不写入**文件，不会把启动器改坏
- 支持当前版本，也按"语义锚点"尽量兼容未来版本（见下文限制）

## 功能

拖入 exe 后会出现菜单：

| 选项 | 行为 | 备注 |
| --- | --- | --- |
| **1. 解锁下载** | 把限制任务换成 `ModDownload.DlClientListLoader`，恢复版本列表与安装；顺带恢复"修改版本"页的原版卡片 | 更新功能保持原样；官方更新后需重跑一次 |
| **2. 解锁下载并屏蔽更新** | 在 1 的基础上：`get_HasUpdatePermission` 恒返回 False、4 处"检查更新"入口置空、`--update` 自我替换调用丢弃参数 | 防止补丁被自动更新覆盖 |
| **3. 卸除补丁** | 用同目录 `xxx.exe.bak` 覆盖当前 exe，还原为原版 | 依赖首次修改时自动生成的备份 |
| **(1、2 都会做) 恢复整合包安装** | 官方版里 `ModModpack.ModpackInstall(String,String,String)` 的派发代码被编译器整段删掉了；工具重新生成这段派发（CurseForge / HMCL / MMC / MCBBS / Modrinth / 启动器整合包 / 普通压缩包），放进新增的 `.pclx` 段并把方法 RVA 指过去 | 文件会增大约 1 KB；`.bak` 仍是原版，可随时还原 |

## 使用方法

把 PCL 的 `Plain Craft Launcher 2.exe` 直接拖到 `PclUnlockPatcher.exe` 上，
窗口会停下显示当前状态与三个选项，键入数字回车即可；直接回车＝取消。

也可以用命令行（不会弹菜单，适合脚本/批处理）：

```bat
PclUnlockPatcher.exe "D:\PCL2\Plain Craft Launcher 2.exe" --unlock-only
PclUnlockPatcher.exe "D:\PCL2\Plain Craft Launcher 2.exe" --block-update
PclUnlockPatcher.exe "D:\PCL2\Plain Craft Launcher 2.exe" --uninstall
PclUnlockPatcher.exe "D:\PCL2\Plain Craft Launcher 2.exe" --dry-run
```

其它参数：`--no-backup` 不生成 .bak；`--out <路径>` 输出到另一个文件。

### 出错时会明确告诉你是哪一种

| 提示 | 含义 | 处置 |
| --- | --- | --- |
| `无法读取该文件…正由另一进程使用` | 启动器还开着，或文件被锁 | 完全退出 PCL 后重试 |
| `目标目录不可写` + `[诊断] 检测到环境变量 DSH_…` | 工具跑在沙箱/受限终端里，只允许写它的工作区 | 用资源管理器**直接双击**本工具 |
| `目标目录不可写` + `[诊断] 临时目录可写、仅该目录不可写` | 目标目录权限/安全策略问题 | 检查目录安全属性，或以管理员身份运行 |
| `未找到可注入的限制分支` | 该版本结构与已知版本都不同 | 不写入任何文件；可提 issue 附版本号 |

## 工作原理（简述）

1. 用 **Mono.Cecil** 读取目标程序集元数据，按**语义锚点**定位补丁点，而不是写死字节偏移：
   - 解锁：`PCL.PageDownloadInstall.LoaderInit` 中形如
     `ldstr "关闭下载" … newobj LoaderTask::.ctor` 的那一整段参数求值；
     找不到时退化为"引用限制文案（含"不再提供/无法提供…下载"）的 lambda"反查。
   - 屏蔽更新：方法名 `PCL.ModSecret.get_HasUpdatePermission`，
     以及全程序内所有指向 `ModSecret.UpdateCheckByButton` / `UpdateReplace` 的 `call`。
2. 全部改动都是**等长替换**：只覆盖原有指令字节（`ldsfld` + `nop` 填充、
   `ldc.i4.0; ret` + `nop`、`call` → 5×`nop` / 参数个数个 `pop`），
   不搬方法体、不改 PE 头与元数据 → 文件大小、RVA、资源、强名称状态均不变。
3. 替换前做安全检查：方法含异常处理块则跳过、替换区间内不得有外部跳转目标、
   修改区域不得重叠或越界；写完后再用 Cecil 回读校验并打印每个修改点的偏移与字节数。

4. 整合包安装恢复是唯一的**非等长**改动：先按语义定位 3 参数 `ModpackInstall`，
   在它抛出限制提示的那条 `ldstr` 处切开方法体，保留前半段（压缩包类型识别）原字节，
   重新生成后半段 `switch` 派发、把原来的 `finally` 处理器整段搬过去、按新偏移重算异常表；
   然后**复用 `.reloc` 的段头**新增一个 `.pclx` 段存放新方法体（重定位目录随之指向段内副本），
   最后改写 MethodDef 表里该方法的 RVA。原文件所有字节位置不变，所以等长补丁的偏移依然成立。
   写入后会用 Cecil 回读，并在内部核对派发调用、异常表、以及在 .NET 里真正 JIT 编译该方法体。

为什么不用 Cecil 直接重写整个程序集？因为 PCL 把 `MeloongCore`、`PCLCS` 等私有程序集
内嵌在自己的资源里，Cecil 写回时需要解析这些引用，脱离原程序无法完成；等长字节改写没有这个问题。

细节见 [docs/技术说明.md](docs/技术说明.md)。

## 从源码构建

需要 Windows + **.NET Framework 4.8**（Win10 1903+ / Win11 自带），无需 Visual Studio：

```bat
build.cmd
```

它实际执行的就是一行编译器命令（见 `build.cmd`），产物在 `dist\`。
`lib\Mono.Cecil.dll` 会被编译进程序（`/resource`），因此发布物是**单个 exe**。

## 已知限制

1. 整合包安装只恢复"安装"这一步。官方版里另外两处也被删掉了，工具不去碰：
   - 资源站"整合包详情页"的一键安装按钮（该分支需要新增元数据行）；
   - 资源页右下"安装已有整合包"按钮（该方法需要新增局部变量签名与字符串常量，超出本工具的改写能力）。
   替代做法：把整合包 zip **直接拖进 PCL 窗口**，或命名为 `modpack.zip` 放到 PCL 目录下启动，
   两种方式都会走到已恢复的安装流程。
2. 整合包安装恢复依赖 PCL 保留 `InstallPack*` 这些函数体（2.99.0.0 与 2.13.x 都保留）。
   若未来版本把它们也删了，工具会报告"此版本缺少安装函数 …"并跳过这一项，其余补丁照常生效。
2. 模式 1 下，官方自动更新会用新版本覆盖 exe，解锁随之失效；届时重跑本工具即可。
   想一劳永逸用模式 2。
3. 若未来版本彻底改了限制实现方式（既无限制文案、也无 `关闭下载` 假任务、
   `DlClientListLoader` 被改名），工具会报告"未找到可注入的限制分支"并**不写入**。
4. 只支持 .NET Framework 4.8 上的 PCL2（本项目未适配其他启动器）。
